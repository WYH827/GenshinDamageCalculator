# 快速导入数据说明

核对日期：2026-11-08。

## GGScanner

- [抓包导出实现](https://github.com/Anyrainel/GGScanner/blob/main/genshin/src/capture/player_data.rs)：输出format=GOOD、version=3、source=yas-GOODScanner，装备location为所属角色的GOOD名称；圣遗物level=抓包level−1。
- [导出模型](https://github.com/Anyrainel/GGScanner/blob/main/genshin/src/scanner/common/models.rs)：characters/key，weapons/key/level/ascension/location，artifacts/slotKey/mainStatKey/rarity/level/substats/location。副词条value已是游戏显示单位，rolls与initialValue只是额外信息，不重复叠加；unactivatedSubstats不导入。
- [GOOD键转换](https://github.com/Anyrainel/GGScanner/blob/main/genshin/src/game_data/types.rs)：英文名称按空格首字母大写，去除非ASCII字母数字字符。

## Enka

- [官方API文档](https://api.enka.network/#/api)、[中文API文档源码](https://github.com/EnkaNetwork/API-docs/blob/master/api_chs.md)、[原神数据结构](https://github.com/EnkaNetwork/API-docs/blob/master/docs/gi/api.md)。
- UID端点为`https://enka.network/api/uid/{uid}/`。解析avatarInfoList与equipList；武器基础攻击力取flat.weaponStats中的FIGHT_PROP_BASE_ATTACK；圣遗物主副词条取flat.reliquaryMainstat/reliquarySubstats的statValue。百分数已经是20表示20%的单位，不再乘100。
- 只有公开展柜详情可读；无avatarInfoList时提示开启角色详情。端点自定义User-Agent，尊重ttl缓存，不批量枚举UID。
- 本轮使用官方文档示例UID验证了服务器200返回、浏览器经本地代理读取及四位角色装备解析。用户实际UID可能受展柜公开状态、缓存或服务状态影响。

## 本地参考数据

`src/data/import-reference.json`为精简快照，来自[EnkaNetwork/API-docs的原神store](https://github.com/EnkaNetwork/API-docs/tree/master/store/gi)：

- avatars.json、locs.json：角色ID、GOOD英文键与中文名称，共156条角色/元素形态记录。
- weapons.json、curves.json、locs.json：256把武器名称、基础值、成长曲线、突破加算；基础攻击=round(初始基础值×等级曲线[level−1]+突破加算[ascension])，不计副词条和被动。
- relic_levels.json：按rarity和level+1取主词条实际数值，百分数换算后按游戏显示精度舍入。

快照无需用户导入时联网下载。新增武器或角色可通过更新参考文件扩充；无法确定的武器不会猜成满级数值。未知角色仍显示原ID/GOOD键供选择。

## 写入范围

角色name/level/constellation（等级同步stars）、武器name/atk/substats、圣遗物主副词条按独立勾选项写入；保留原ID、关联、基础三维、突破属性、效果、技能与时间轴。

圣遗物保存mainStats类型、mainStat20开关、mainStatValues自定义值。20级且5星采用固定数值，其他等级采用来源值；空装备部位为0。类型只用原有选择列表，充能沙/治疗头等在预览提示并映射NOT IMPORTANT。旧importedMainStats导入时迁移为上述结构，移除前缀与旧覆盖字段。旧数据未记录等级时用数值是否等于对应固定值判定开关。

GOOD的命座取characters.constellation；Enka取talentIdList长度，缺省0。GOOD武器副词条使用BaseProps中非基础攻击项乘PropGrowCurves所指的等级曲线；Enka使用weaponStats非FIGHT_PROP_BASE_ATTACK项。均输出直接数值模式，百分比不重复换算。

UID在发起合法查询时保存在本地teyvat-studio.last-enka-uid，关闭窗口与刷新不丢失，也不因此自动查询。


2026-11-10更新：所有可用导入选项默认勾选，新增独立的套装名字导入。套装参考数据来源于 https://raw.githubusercontent.com/EnkaNetwork/API-docs/master/store/gi/relics.json 的Sets.Name，结合已有中英文locs生成GOOD键/中文名映射及Enka名字Hash映射，当前65套。GOOD用setKey匹配英文名称（忽略大小写及标点）；Enka读取flat.setNameTextMapHash。4件套、2+2、2件套和散件按有效部件计数判断，无法识别名称时保留旧套装名。导入20级但不含5星标记时保留自定义数值，不勾选20级5星圣遗物。


2026-11-10实测补充：通过官方示例UID获取4个公开角色，接口 `fightPropMap["1"]` 是基础HP、`["7"]` 是基础DEF、`["4"]` 是角色与武器合计基础ATK。示例安柏合计897.3515625，天空之翼90级6突破未取整基础674.334546，拆得角色223.0170165；不能把API值直接作为角色ATK再叠武器。按Enka武器BaseProps×成长曲线+BasePromote计算未取整数值；缺少武器资料时尝试角色同等级与突破的BaseProps/PropGrowCurves/PromoteProps；无法可靠获取则不导入三维。并未使用不确定的SDK字段baseHP/baseAttack/baseDefense。

实时接口套装哈希可能与store/gi/relics.json的Sets.Name不同，例如宗室实时1751039235、资料表1750139131；增加flat.setId=15007回退解决。头像SideIconName来自store/gi/avatars.json，武器优先flat.icon，圣遗物根据生效套装寻找EquipType=0的花，2+2保留两花。角色、武器和圣遗物保存图片URL，不把网络图片下载嵌入用户方案。

批量导入调用同一解析和字段选择逻辑，四个目标ID保持不变，全部字段映射检查完成后一次性更新，避免半完成导入。测试fixture来自上述公开接口，已去除玩家昵称、UID、签名等玩家字段，仅保留角色与装备样例用于回归。
